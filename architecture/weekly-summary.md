# Weekly summary (`WeeklySummary/`)

*Part of the Emojily architecture reference. Up: [OVERVIEW.md](../../OVERVIEW.md) · Index: [§6 Features](../../OVERVIEW.md#6-features)*

---


Two period modes — `completedCalendarWeek` and `trailingSevenDays` — with stats, a
week-over-week comparison, and a shareable image. Free.

**On-device narrative summary — shipped, free (B-10).** A natural-language recap of the week,
generated by Apple's `FoundationModels` on device. `WeeklyNarrativeCard` renders in
`WeeklySummaryView` as the first item inside the `hasData` branch, above the highlights. It spent a
release on the Insights tab — a free sentence whose only in-app entry point is premium is backwards —
and came back because **the sentence is what the shared image is for**: a week in the reader's own
words is the part worth sending someone, and on Insights it could not reach the share sheet at all.
The trade is stated plainly: the in-app button into this screen sits inside `gatedContent`, so a free
reader now meets the sentence through the weekly notification rather than by browsing.

**`WeeklySummaryView` owns the narrative view model rather than a section view**, because the
sentence is not only rendered — `weeklySummaryShareSnapshot` needs the text too, and a narrative
hidden inside a child view could not reach it. The share image renders the sentence only when the
screen was showing one; nothing is generated for the share sheet, since an image saying something the
screen behind it did not is a different week to whoever receives it.

**Free, with no `PremiumFeature` case.** It only exists on the minority of devices with Apple
Intelligence, so gating it would sell most subscribers something they cannot use. This follows the
precedent the rest of the app already sets for trust signals.

**The gate is resolved synchronously before the first paint.** `WeeklyNarrativeComposer.blockingReason`
is input-side only, so a device that can never generate shows no card at all rather than a shimmer
it would immediately discard. `isGenerating` is only ever set
when the model will actually run. Generation is also skipped for an unchanged week —
`WeeklyNarrativeFacts` is `Equatable`, and a CloudKit sync ping is not a reason to rewrite a sentence
the reader is already looking at.

**Voice controls are hidden on this surface** until B-10d. Each voice is its own tone review, and
the corpus has only been run against `plain`.

**The known quality limits ship with it, knowingly.** The body still restates the headline on many
weeks and still recites the fact-sheet labels — see `BACKLOG.md` B-10, where eight measured attempts
to fix this are recorded, all of which made it worse.

| Piece | Role |
| --- | --- |
| `WeeklyNarrativeFacts` | The facts the model may see: counts, moods, tags, comparison, plus the week's notes when opted in |
| `WeeklyNarrativeNote` / `WeeklyNarrativeNoteCollector` | One day's own words, truncated at 200 chars and 700 combined; collected only where something explicitly asks |
| `WeeklyNarrativeLanguage` | `NLLanguageRecognizer` detection for notes, and the output language the answer must come back in |
| `WeeklyNarrativePrompt` | The **frozen** safety rules plus the fact sheet builder |
| `WeeklyNarrativeVoice` | Plain / Warm / Poetic / Dry, plus debug-only Coach — register only, appended to the rules, never substituted |
| `WeeklyNarrativeRule` | The ten safety rules as data, so the harness can switch one off and watch what changes |
| `WeeklyNarrativeLocalePolicy` | Which languages generation is allowed in; `reviewedLanguageCodes` is `["en"]` today |
| `WeeklyNarrativeEngine` | The seam over `FoundationModels`, so everything above is testable without an Apple Intelligence device |
| `FoundationModelsWeeklyNarrativeEngine` | One of two files that import `FoundationModels` — see *Daily Echo* below |
| `WeeklyNarrativeComposer` | The gate order, and the guarantee that every branch returns *nothing* rather than something invented |
| `WeeklyNarrativeCard` | The presentation — hero mood, the sentence, voice chips, disclaimer. Lives in the feature folder because it is what would ship |
| `WeeklyNarrativeViewModel` / `DebugWeeklyNarrativeView` | The Debug Tools harness — mock week or live journal, reviewed languages or any |

**There is no deterministic sentence any more.** A template floor made sense while the card opened
this screen and an empty card read as a bug; it went when the card moved, and it has not come back
with it — the highlights below still carry the screen, and a card that is simply absent on a device
that cannot generate is indistinguishable from a week with nothing to say. The cost, stated plainly:
the narrative reaches only reviewed-language users on Apple Intelligence devices, exactly the
audience *Daily Echo* reaches, and everyone else sees the rest of the screen.

**The model fills a two-field schema, not a blank.** `WeeklyNarrativeDraft` — `headline` (≤6 words)
and `body` — is the shape fix for a rule that kept failing in opposite directions. The `@Generable`
mirror lives inside `FoundationModelsWeeklyNarrativeEngine`, one of the two `FoundationModels*Engine`
files that import the framework, so the composer and its tests still run on machines with no Apple
Intelligence. An empty headline is a
legitimate answer and becomes `nil`; an empty body falls back.

**Structure is validated, tone is not, and that split is the whole design.**
